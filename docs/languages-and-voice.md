# Working languages and live voice

Updated 2026-10-11 on `frontend-aarush`.

Footnote offers 31 working-language choices in `mobile/src/domain/languages.ts`. Choosing a language changes app-authored labels, glossary content, date-picker locale, native search labels and interface direction. Arabic and Hebrew use right-to-left layout. Original document excerpts, provider names, voice names and live captions remain verbatim. Gemini receives the working locale for new document explanations; changing the UI language does not rewrite an existing provider-generated analysis.

Translations are bundled in `mobile/src/localization/*.json`. They were generated entirely offline with a pinned NLLB model through `mobile/scripts/translate-ui-offline.py`. No UI phrases were sent to Gemini or another hosted translation service. The model and build-only Python dependencies are not shipped in the app. Common controls have curated overrides; Spanish glossary entries reuse the repository's existing translations. Native speakers have not reviewed the generated clinical prose.

The iOS bundle declares the 31 localizations. App-owned controls follow the saved working-language preference; system permission dialogs follow the device's system language. Flags are bundled from FlagCDN and work offline. They complement explicit language names rather than implying a language belongs to only one country.

The voice chooser contains only named voices from the connected ElevenLabs catalog whose `verified_languages` metadata matches the working language. Metadata was read from the provider on 2026-10-11 and stored server-side. An empty match shows a recoverable unavailable state. This is stricter than treating every multilingual voice as native in every language. The chooser has no working-language selector; only its illustration, name and preview controls page. The header and confirmation button remain stationary. Existing preview clips introduce the voices in English.

A single orb tap starts a saved-bill conversation or toggles its microphone. Long-press opens compact voice controls. Captions are enabled by default, can be disabled locally, and sit above the orb. Minimized conversations continue; navigation, backgrounding and changes to bill context, language or voice end the session. Typed questions use ElevenLabs `sendUserMessage`; typing uses `sendUserActivity` to reduce agent interruptions. The existing `show_line_item` and `show_price_check` client tools highlight evidence-linked findings without changing financial data.

Live calls require a reachable configured backend and an eligible saved analysis. Private provider keys remain server-side; the app receives short-lived WebRTC tokens. A voice/language/model mismatch returns a recoverable error. Hebrew and Thai may require the existing recorded-question fallback. The [ElevenLabs SDK reference](https://elevenlabs.io/docs/eleven-agents/libraries/java-script) documents the messaging, activity, microphone and client-tool methods used here.
